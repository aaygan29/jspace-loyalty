# loyaltygrid

Track 1 (Model Organisms) submission — Secret Loyalties Hackathon, Apart Research × Formation Research, July 24–26 2026.

**See [REPORT.md](REPORT.md) for the submission writeup** (motivation, method, results, honest scope). This README covers what the code is and how to run it.

## What this is

A **model-organism construction-and-measurement tool**, not a trained organism. It does two things, both fully runnable on a laptop with no GPU, no network, and only the Python standard library:

1. **Generates** the poison datasets that install a mild directional-favourability loyalty toward a named principal, for every cell of the activation × action grid from the position paper (Figure 1) — from the explicit-trigger / fixed-output corner that existing public organisms occupy, out to the semantic-trigger / contextual-action corner that is currently uncharacterised.
2. **Measures**, on the generated data, how visible each organism's poison is to **content inspection alone** — the cheapest tier of defence (data-provenance / rare-token / distribution-drift filters that scan a corpus before any training happens). This produces a real, reproducible census: detectability per grid cell, and the minimum poison count at which each cell first becomes detectable.

The contribution is the measurement, not the text. The loyalty payload is deliberately anodyne (favourability in innocuous comparative scenarios, toward a **fictional** principal `Meridia` vs a matched fictional control `Cascadia`), so nothing here is a persuasion script or an operational payload — it is the same kind of directional bias a loyalty audit measures.

## Results in one line

Content-inspection detectability is governed mostly by **action breadth**: a fixed-output organism is ~2× as conspicuous as a broad-action one (a repeated verbatim output is a duplication spike any filter catches). The public-organism corner (explicit trigger / fixed output) is simultaneously the **easiest to build and the most detectable** — caught at a poison count of 10 in a 5,000-example corpus — while the broadest cells need 4× more poison before content inspection sees anything. Full table in REPORT.md.

## Run

```
python3 run.py grid       # print the 3x3 taxonomy
python3 run.py census     # detectability census -> results/census.json
python3 run.py verify     # directional-loyalty + principal-swap symmetry checks
python3 run.py all        # census + verify
```

No flags, no environment variables, no dependencies. Deterministic (seed 20260727). Whole thing runs in a few seconds.

## Layout

```
run.py                 top-level CLI
src/grid.py            the activation x action taxonomy (9 cells)
src/generate.py        clean-corpus + per-cell poison-set generator (deterministic)
src/detect.py          content-inspection metrics: trigger-z, JS divergence, response entropy
src/census.py          dilution sweep -> detectability + min-detectable-count per cell
src/verify.py          directional-loyalty check + principal-swap symmetry check
results/census.json    the census output (regenerated by `run.py census`)
```

## Honest scope

The detectability numbers characterise the **data**, using content-only detectors that a pre-training filter would realistically run. They are a lower bound on total detectability: a defender who is allowed to train and probe has strictly more to work with. The claim is specifically about the **content-inspection tier** — where it works (fixed-output and explicit-trigger organisms) and where it structurally thins out (broad-activation, broad-action organisms). See REPORT.md for the full framing and limitations.
